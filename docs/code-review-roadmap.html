LODVault · Internal review · July 2026

Code Review: Issues, Gaps & Top-10 Quick Wins

Scope: full extension source (scripts/, pages/, styles/, manifest.json) Version reviewed: 2.0.0

Overall verdict: solid engineering core, unfinished product surface. The storage, sync, and SPA-integration layers are carefully built (tombstone deletes, quota sharding, race-guarded async, verified sync). The main risks are data-safety gaps (SRS progress and deletes are one misclick or one uninstall away from loss) and a layer of UX polish that never shipped: the spaced-repetition plumbing exists but has no user-facing queue, the UI is dark-only with weak keyboard affordances, and destructive actions have no safety net. The good news: the ten highest-value improvements are all small, because the hard infrastructure is already done.

A · Issues found

Grouped by category, ordered by severity within each group. File references point at the reviewed source.

A1 · Data safety most urgent

SRS progress is not backed up and not synced high

Flashcard review history lives in a separate lodVault.flashcardMeta key. The JSON backup exports only settings + entries, and sync.js has no reference to flashcard data at all. Uninstalling, switching devices, or restoring a backup silently wipes every review, streak, and interval the user has earned.

refs: store-core.js:1746–1838 (meta + due logic), popup-app.js:1137–1150 (backup builder), sync.js (no flashcard refs)

Deletes are instant, with no confirmation and no undo — everywhere high

Deleting a word (and its note) is a single click in the popup, the current-word card, the preview page, and the lens. Tombstone sync then faithfully propagates the mistake to every device. The codebase even has a toast/status system that could carry an "Undo" action.

refs: popup-app.js:985–999, 1257–1270, preview.js:499–509

Typing a note on an unsaved word silently force-saves it to Study medium

The note handler catches "Entry not found" and quietly toggles the word into the Study list as a side effect — surprising behavior that is only hinted at in placeholder text.

refs: popup-app.js:67–79

A2 · UX & usability

The SRS has no user-facing review queue high

dueAt and interval are computed per word (hard → 1 day, good → ×2, easy → ×2.5), but the only consumer is a priority boost inside "Smart" order. There is no "Due today" deck, no due-count badge, no daily target — the core loop of every vocabulary tool is plumbed but never surfaced.

refs: store-core.js:1798–1815, sole consumer flashcards.js:254–275

Popup list is capped at 10 items with no filters and no pagination medium

LIST_LIMIT = 10, sorted newest-first, with search as the only narrowing tool. You cannot view "only Favorites" or "only Study", and there is no "show all" escape hatch other than opening the Vault page.

refs: popup-app.js:1018–1023, 1231

Preview rebuilds the entire iframe on every toggle medium

Every favorite/study toggle, delete, or note edit triggers a full renderPreview() — scroll position and collapsed/expanded state are lost each time. Exports also ignore the active search/language filter: "Download HTML" refetches all entries instead of exporting what you see.

refs: preview.js:437–441, 546–583

Missing micro-states: loading, empty CTAs, shortcut help medium

The popup shows "0 saved words" while storage is still loading (no skeleton). Empty states are one plain line of text with no call to action. Flashcards supports ←/→, Space, 1/2/3, R — but the UI never tells anyone.

refs: popup.html:153–155, flashcards.js:208–227 (undocumented shortcuts)

Pronunciation is missing exactly where you read the word low

Audio playback exists in the popup, preview, and flashcards — but not in the page banner on lod.lu itself and not in the LOD Lens overlay. The two surfaces where a learner encounters the word in context have no 🔊 button.

refs: page-banner.js (no audio), lens-overlay-shell.js:283–320 (no audio)

A3 · Accessibility & theming

Dark-only UI, no reduced-motion support, zero :focus-visible styles medium

All five stylesheets hard-code a dark palette; the only prefers-color-scheme rule in the repo is in pages/import.html. There is no prefers-reduced-motion handling (audio-pulse and dot-pulse animations run unconditionally) and not a single :focus-visible rule — keyboard focus is effectively invisible, including on the flashcard itself which is a tabindex="0" button.

refs: styles/*.css, flashcards.html:80, content.css:78–79

Keyboard & screen-reader gaps in Lens and flashcards medium

The flashcard global keydown handler has no event.target guard — pressing Space/1/2/3 while a <select> is focused hijacks the dropdown. In the Lens, sentence word-chips are <span>s and accordion headers are <div>s (not focusable, no aria-expanded), the dialog has no focus trap or aria-modal, and lookup status is not aria-live. Banner Fav/Study buttons lack aria-pressed. Muted text #5a7d96 on #111d2e is ≈3.8:1 — below WCAG AA 4.5:1 for small text.

refs: flashcards.js:208, lens-render.js:68, 148–157, lens-overlay-shell.js:33, page-banner.js:317–323

A4 · Code health

Triplicated core logic across storage, sync, and the background bundle medium

normalizeEntry, normalizeSettings, normalizeDeletedMap, and the "max of updatedAt/lastVisitedAt/createdAt" timestamp merge exist in three copies (store-core, sync fallbacks, background bundle). Sync key strings ("lodVault.m" etc.) are hard-coded in popup-app instead of imported. Drift between copies is a silent-corruption risk.

refs: store-core.js:241–248, 389–407, sync.js:38–97, popup-app.js:137–141, 1056–1062

Giant single-closure files; list rendering via innerHTML strings low

popup-app.js mixes sync health, backup status, history import, notes, and list rendering in one 1,753-line IIFE. The saved list is rendered as one escaped innerHTML template — currently safe, but fragile to extend. Four near-identical status-tone helpers repeat the same class add/remove dance.

refs: popup-app.js:461–512, 1174–1202

C · Top 10 functionalities — minimal effort, maximum user value

Ranked by value-per-effort. Every item reuses infrastructure that already exists; none requires new permissions, backend work, or schema migrations beyond a tolerant additive change.

S · hours single-digit hour change M · 1–2 days contained feature impact user-visible value
1

"Due today" flashcard deck + due-count badge S · hours impact ★★★★★

Turns the hidden SRS into the product's core habit loop: open flashcards → see "12 due today" → clear the queue. The dueAt field and computeFlashcardDueAt already exist and are already written on every review — this is purely surfacing data that is already there.

How: add a "Due today" option to the existing deck filter in flashcards.js:230–243 (filter entries where meta.dueAt <= now, same check as flashcards.js:259–261), plus a due count in the stats strip next to the existing streak/today numbers (flashcards.js:103–152). Optionally show the count in the popup stats row.

2

Include SRS progress in JSON backup (and compact sync) S · hours impact ★★★★★

Fixes the single worst data-loss hole: today, an uninstall or device switch silently destroys all review history, streaks, and intervals. Users are actively told to "backup before uninstalling" — and the backup doesn't contain their progress.

How: add flashcardMeta to buildJsonExport (popup-app.js:1137–1150) and merge it on restore (max-totalReviews wins per word, same pattern as entries). Sync inclusion can follow later; the backup path alone closes the urgent hole.

3

Undo toast for deletes (or a confirm step) S · hours impact ★★★★☆

One misclick currently deletes a word and its personal note, then syncs the deletion everywhere. An "Undo" window converts a catastrophic action into a harmless one. The status/toast styling and the tombstone infrastructure already exist — undo is just re-adding the cached entry object within a few seconds.

How: in the popup list and preview delete handlers (popup-app.js:1257–1270, preview.js:499–509), snapshot the entry, call removeEntry, show "Deleted word — Undo" in the existing status line; on undo, re-save the snapshot.

4

Popup list filters: All / Favorites / Study chips S · hours impact ★★★★☆

The popup is the daily-driver surface, yet you can't answer "what's in my Study list?" without search gymnastics. Entries already carry favorite/study boolean flags — filtering is a one-line predicate on data already in memory. Pairs naturally with raising or paginating the hard 10-item cap.

How: add a chip row above #saved-list (reuse the sync-language chip styling in popup.html:43), filter displayEntries before the LIST_LIMIT slice (popup-app.js:1231), persist the choice in settings.

5

Pronunciation button in the page banner & LOD Lens S · hours impact ★★★★☆

Hearing the word is one of the most-used features, and it's absent exactly where learners encounter words in context: the lod.lu article banner and the Lens overlay. playLodAudio/createAudioController already handle LOD's OGG URLs and playing-state visuals — this is component reuse, not new work.

How: add the existing audio button markup + controller to the banner row (page-banner.js) and to the Lens word header (lens-overlay-shell.js:283–320), guarded by the same "has audio URL" check used in flashcards.js:376–381.

6

Accessibility quick pass: focus rings, aria states, keydown guard S · hours impact ★★★★☆

A handful of one-line fixes that make the whole app keyboard-usable and screen-reader coherent — and fix the real bug where pressing Space/1/2/3 with a deck <select> focused both rates the card and fights the dropdown.

How: (a) add :focus-visible outlines to the four stylesheets; (b) guard onKeyDown in flashcards.js:208 with an event.target check; (c) add aria-pressed to banner + preview pills; (d) make the Lens status aria-live and give chips/accordion headers role="button" tabindex="0"; (e) bump --muted contrast toward AA.

7

Light theme via prefers-color-scheme + reduced-motion support M · 1–2 days impact ★★★★☆

The UI is permanently dark. Many users read in daylight, and all colors already flow through CSS custom properties — a light theme is a variable re-declaration per surface, not a redesign. prefers-reduced-motion is a two-rule addition for the pulse animations.

How: add a @media (prefers-color-scheme: light) block overriding the :root variables in each of styles/popup.css, flashcards.css, preview.css, content.css, lens-overlay.css (start with popup + flashcards), plus a prefers-reduced-motion block disabling the animations in content.css:78–79.

8

"Export what you see" — filtered HTML/Anki export from the Vault S · hours impact ★★★☆☆

Users filter to their French-translation words or a search result, hit Download, and get everything instead. Exporting the current view makes the feature predictable and enables curated exports (e.g. an Anki deck of exactly one topic).

How: downloadHtml/downloadAnki (preview.js:568–583) currently refetch all entries; pass the already-filtered entry list from the active search/language state instead. One optional checkbox: "Export all words".

9

Streak + today stats in the popup; shortcut legend in flashcards S · hours impact ★★★☆☆

The motivation loop (🔥 streak, reviewed-today count) is already computed by computeFlashcardStreak but only visible on the flashcards page. Putting it in the popup — the surface users actually open — plus a one-line "Space reveal · 1/2/3 rate · R flip" hint makes two existing features discoverable.

How: extend the popup stats row (popup.html:85–104) with two counters fed by the existing streak/today computation; add a static hint line under the flashcard controls (flashcards.html:107–111).

10

Real empty states + 3-step first-run onboarding S · hours impact ★★★☆☆

Today the empty popup says one sentence; the flashcards empty state has no call to action; nothing tells new users that Auto mode, history import, or the Lens selection trigger exist. Better empty states are the cheapest retention feature there is — pure HTML/CSS against states that already exist.

How: replace the one-liners in popup.html:153–155 and flashcards.html:72–74 with a 3-step mini-guide ("1. Open a word on lod.lu · 2. Save to Study · 3. Review here daily") plus a primary button that deep-links to lod.lu or the Vault.
