Independent product & UX review · 23 February 2026

A solid vocabulary vault that needs a clearer study routine.

LODVault makes it easy to save Luxembourgish words while reading, keep them locally, and review them as cards. The next step is not more ways to capture words. Learners need a clear next study action and confidence that their saved work is safe.

The readout

Strong foundation. Uneven prioritisation.

The extension already supports page capture, Lens and sentence lookup, notes, backup and restore, history import, browser sync, export, and flashcards. That is a lot for a small local-first tool. Its main screens, however, put data-management controls ahead of the learner's next task.

Product direction: make the vault support a simple daily study habit instead of presenting a long list of controls. Put "What should I study?" and "Is my work safe?" ahead of sync details, export formats, and raw totals.

Issues found

Fix trust and focus before adding breadth.

These findings come from the product and code, rather than from earlier repository reviews. Severity reflects the likely effect on learners and their confidence in the app, not how hard each change is to build.

P0 · trust

Language selection is destructive

"Saved languages" sounds like a sync preference. Instead, changing it rewrites every saved entry and removes translations that were not selected from local storage. A learner trying to reduce sync size can lose useful French, German, or English context.

Evidence
scripts/store-core.js
setSyncLanguagesDirect() filters the full entry map before persistence.

pages/popup.html calls this "Saved languages."

Recommendation: retain all local translations; filter only the compact sync payload. If removal remains intentional, require an explicit destructive confirmation and a restore path.

P1 · UX

The popup has no primary job

The first screen shows Auto mode, language settings, sync capacity, pull and push, the current word, counts, search, backup, restore, and history import. Maintenance controls compete with the task the learner came to do.

Evidence
pages/popup.html contains all control groups in one vertical flow.

styles/popup.css fixes the popup at 420px wide.

Recommendation: default to Current word + Study now + recent words. Move sync, history import, and backup behind a compact "Data & settings" disclosure or dedicated settings page.

P1 · learning

Due-state is computed, not productised

Ratings calculate dueAt and a simple interval, and "Smart" sorting considers due cards. But there is no due count, daily target, or "Start due review" button. Opening a vault of 406 entries as a 406-card deck makes it hard to know where to start.

Evidence
scripts/store-core.js stores dueAt and interval.

pages/flashcards.html offers Study / Favorites / All; no Due deck.

Recommendation: surface a Due deck as the default, with "12 due · 5 new" and a small daily target. This reuses existing review metadata.

P1 · safety

Destructive actions lack recovery

Remove actions delete an entry immediately in the popup and Vault. Tombstones keep sync consistent, but the learner gets no confirmation, undo option, or recycle bin. One accidental click can remove a note and review history.

Evidence
scripts/popup-app.js and scripts/preview.js call removeEntry() directly.

removeEntryDirect() deletes from the entry map.

Recommendation: show an Undo toast for 6 to 10 seconds with the complete entry in memory. It is faster and less disruptive than modal confirmation.

P2 · adoption

Lens is powerful but intentionally hidden

The floating trigger appears only after a context-menu or keyboard action loads the runtime. That respects privacy, but first-time users are not told about the shortcut or the two-step activation.

Evidence
scripts/selection-trigger.js hides the trigger until LodVaultLensRuntime exists.

Shortcut: Alt+Shift+L.

Recommendation: add a one-time "Translate selections with Lens" hint in the empty vault and popup, including the shortcut and context-menu route.

P2 · retrieval

Three fixed lists do not scale

Favorite, Study, and History describe status, not why a learner saved a word. There is no way to group "work vocabulary," "A2 verbs," or "words from today's article" and then review or export that group.

Evidence
scripts/store-core.js normalises only favorite, study, and history memberships.

Vault filtering is language + search + sort.

Recommendation: start with optional freeform tags, not full deck management. Tags unlock filtering, review selection, and purposeful exports.

P2 · clarity

Backup and restore do not show consequences first

Backup status is visible, but restore merges a file as soon as the user chooses it. There is no chance to see how many entries are new, changed, or conflicting before the import.

Evidence
pages/import.html describes a merge and has one file input.

importJsonDirect() merges while parsing the selected file.

Recommendation: parse first, show a compact "will add / merge / skip" summary, then let the user confirm. Keep the present merge default.

P2 · quality

Firefox release lint is not clean

The build succeeds, but Firefox lint reports 17 warnings: there is no explicit data-collection declaration and dynamic innerHTML assignments are flagged. Much of the dynamic text is escaped, so the warnings do not prove an exploit. They still make release checks noisier than they should be.

Evidence
npm run lint completed with 0 errors and 17 warnings.

Warnings include MISSING_DATA_COLLECTION_PERMISSIONS and UNSAFE_VAR_ASSIGNMENT.

Recommendation: add Firefox's no-data declaration and reduce/suppress documented safe markup construction. Treat any unsanitised boundary as a security review item.

Product gaps

What the learner cannot yet do.

The extension covers a lot for a local-first browser tool. It is missing a few connecting pieces that help people stay motivated, find the right words, trust their data, and return to study with little effort.

Habit formation

No daily goal, due count, reminder, "continue yesterday's session," or visible progress toward a manageable practice. The app records streak data but does not use it to shape behaviour.

Meaningful grouping

No custom tags or learner-defined groups. The vocabulary collection cannot mirror the learner's course, job, reading source, grammar topic, or confidence level.

Safe data operations

No preview before restore, undo after deletion, or clear distinction between local preservation and sync payload reduction. The data model is stronger than the reassurance around it.

First-run guidance

The empty state is one sentence. It does not explain the page banner, auto mode trade-off, Lens, or the next action that produces a useful first flashcard session.

Focused vault browsing

The full Vault has search, language filter, and sort, but lacks quick views for Study, Favorites, History, no-note, no-translation, and due words. Those are common ways to decide what to clean up or study.

Feedback after actions

Most mutations rerender silently. Save/remove/import/sync flows would feel safer with concise outcomes, retry affordances, and a visible last-successful-sync timestamp.

Suggested sequence

Build a clearer study routine in three small releases.

Release 1 · trust

Protect the vault

Make sync-language selection non-destructive, add undo for deletion, show the last successful sync, and resolve Firefox lint warnings. Fix these trust problems before adding engagement features.

Release 2 · focus

Give each screen a clear purpose

Default flashcards to Due, add quick Vault views, and hide maintenance controls behind a compact popup section. A learner should immediately see what they can do next.

Release 3 · habit

Make it easier to come back

Add a daily target, session resume, and a one-time getting-started guide. Test the first save and first review with a small usability study.
